# ADR-0003: Authentication: Better Auth on the Drizzle adapter

Status: Accepted
Date: 2026-09-29
Doc: TECH_STACK.md

## Decision
Better Auth 1.7 with email/password and optional passkeys/OAuth, backed by the
same PostgreSQL through the Drizzle adapter.

## Context
Deployment must be self-hostable by a non-devops person, and the owner is
solo. The product only needs to identify a person: creator/collector/validator
are project-scoped Memberships in the domain, not auth roles.

## Alternatives considered
- Passport + JWT + argon2, first-party NestJS guards — no extra dependency, but password reset, sessions and hardening become ours to build and maintain.
- External OIDC provider (Authentik/Keycloak) run by the operator — strong SSO, too heavy for the non-devops self-hosting target.
- Hosted providers (Clerk, Supabase Auth) — violate the self-hostable requirement.

## Consequences
Auth schema lives in Postgres alongside the domain, managed via Drizzle.
Revisit if enterprise SSO or external-identity federation becomes a need.

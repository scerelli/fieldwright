# ADR-0001: Server data layer: PostgreSQL, PostGIS and Drizzle

Status: Accepted
Date: 2026-09-29
Doc: TECH_STACK.md

## Decision
PostgreSQL 18 with the PostGIS extension, accessed through Drizzle ORM 0.45;
schema changes are forward-only SQL migrations generated by drizzle-kit 0.31.

## Context
Sites carry geometry (point, line, polygon) and the server must query
spatially; visits and detections are versioned and audit-heavy. The owner is
solo and wants one TypeScript toolchain. The brief left the ORM open, naming
Prisma vs Drizzle/Kysely as the unresolved choice.

## Alternatives considered
- Prisma — strong tooling, but weaker native PostGIS type support and awkward for spatial predicates.
- Kysely — query builder only; no migrations or relations layer of its own.
- Prisma with isolated raw spatial SQL — two query paradigms in one codebase.
- Atlas or Flyway migrations — a second tool with no TypeScript schema integration.

## Consequences
Locks the server data layer to Node/TypeScript and to Drizzle's migration
workflow; spatial queries are authored in Drizzle's SQL layer. Revisit if
Drizzle stalls or a requirement outgrows its spatial support.
